# AZ9 Digital

Arabic-first digital product platform for AZ9 Digital.

## Internal product operating principles
These principles guide product decisions, interface behavior, generated plans, and future integrations. They are operating rules rather than public slogans.

1. **Begin with the user's desired outcome.** Clarify goals and constraints before proposing features.
2. **Build on proven foundations.** Prefer reliable tools, standards, tested patterns, and existing integrations over rebuilding solved problems.
3. **Make every workflow useful.** Produce a concrete artifact, a clear decision, or an actionable next step.
4. **Verify before claiming readiness.** Distinguish demos, local-only features, connected integrations, and tested production features.
5. **Reduce friction.** Keep common tasks short, defaults sensible, Arabic-first, mobile-friendly, and accessible to beginners.
6. **Design for iteration.** Use modular components and clear interfaces so future improvements do not require rebuilding everything.
7. **Be honest about uncertainty.** Label estimates, disclose assumptions, and never invent completed work, integrations, or customer results.
8. **Protect users by default.** Minimize data collection and keep private credentials and sensitive integrations on a secure server.
9. **Test the whole journey.** Check accessibility, responsive behavior, errors, empty states, links, and real outcomes, not only visual appearance.
10. **Prioritize compounding improvements.** Favor reusable capabilities, automation, and templates that benefit multiple workflows.

## Repository files
- `index.html`: site structure and Arabic/English content
- `styles.css`: responsive visual system
- `script.js`: local interactions and project-planning tools
- `assets/az9-mark.svg`: vector brand mark

## Local run
Open `index.html` in a browser. No build command is required.

## Deploy
Render Static Site or Cloudflare Pages; publish directory is the repository root and build command is empty.

## Production boundaries
- The AI assistant remains a demo until a provider is integrated securely server-side.
- The project form currently generates a local summary and does not send leads to a server.
- Project budget and timeline values are planning aids, not binding quotations.
- Use verified claims only. Do not present demos as connected services.
